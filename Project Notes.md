# Lessons Learned
- marker-pdf was suggested as a ingestion tool. This is a large, multimodal package using heavy AI. The goal of this project for me is to develop local building blocks myself, using this level of package would defeat the purpose
- tables in the manual are very poorly designed for machine reading. You need a lot of human context to join the data together. There is a lot of row and column merges which make the tables visually nice, but hard to ingest. Tried to ingest the raw text and use it as context, but results were hit or miss. Need foundational LLM to translate tables to JSON for reliable retrieval
- I tried to use TOC(table of contents) retrieval as a chunking indexing method. Tried to have one model match the user question to a chapter. But the chapters don't have enough keyword context explaining what they contain. For example the 'camera flash memory' is listed under 'common specifications', but the model doesn't have enough context to look for that parameter under that heading.
- Tried to have local llm make a summary of each chapter chunk, to use for routing, but again keywords got lost and llm was not able to retrieve all needed data
- Moved to local Qwen VL model. Gemini Hydrogen (and other models) are prone to frequent service outages and very long processing times 5 minutes+ for a table.
- When using the vision model to analyze table data, the schema design matters. I first did a very general schema which duplicated many repeated header strings, which burned tokens and hit my GPU memory limit. The model would respond with truncated json object, breaking the pipeline. A flatter, simpler schema implementation fixed this.
- Qwen3.5 took 15 minutes and failed on my system. Llama3.2 was not able to answer multi-stage questions (lookup all models that have C-mount Lens). Phi4-mini-reasoning retruned accurate multi-stage answers quickly. It is English only model.
